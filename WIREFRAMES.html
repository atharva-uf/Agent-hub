Annotations — Screen 02
C
Commit metadata stripCommit SHA (mono, 7 chars), truncated message, open PR count, branch selector, build status, and relative timestamp — all in one horizontal scannable row below the description.
D
Branch selectorInteractive dropdown defaulting to the repo's default branch. Lets the developer target a specific branch before triggering an agent task — state is local, no network call.
E
Primary CTA — Run Agent TaskPresent in the repo header and in the agent panel's empty state. Scrolls to the agent panel and opens the task modal via a custom window event (no prop drilling).
F
Insight cards6 read-only metrics giving context before a task is triggered. Stars, contributors, test coverage, open issues, deploys, avg PR time. No interaction — they inform, not control.

Annotations — Screen 04
I
6-step execution timelineInitialize → Analyze → Install → Test → Report → Finalize. Each dot transitions: pending ○ → active ⟳ → success ✓ / error ✗. Connector lines turn green as steps complete.
J
Active step — pulse indicatorThe active step dot animates with a pulsing ring. A low-noise "something is happening" signal that works without reading any text. Stops on completion or error.
K
Semantic log level colorsINFO (blue) · CMD (purple) · OK (green) · WARN (amber) · ERROR (red). Maps to terminal conventions developers already know from CI/CD systems and shell sessions.
L
Auto-scroll to latest lineTerminal scrolls to the newest log line as each streams in — matching the behaviour of tail -f. Manual scroll up is preserved until a new run starts.
M
Three independent success signalsStatus badge (top) + all-green timeline + result summary card appear simultaneously. A developer at any scroll position receives an unambiguous completion signal without scrolling.
N
Confidence rating"High confidence" or "Review recommended" — a second-order signal beyond pass/fail. Surfaces whether the agent is certain of its output, not just whether the run completed.
O
One-click retry — no dialogIn-flight timers are cancelled and state resets immediately. No "Are you sure?" dialog. A developer who pressed Retry meant to press Retry — confirmation dialogs add friction at the worst moment.
P
Execution details drawerLog level counts (INFO / CMD / OK / WARN / ERROR), environment context (node, runtime, region, runner), and per-step duration breakdown. The post-mortem view — assembled for the developer so they don't have to dig.
